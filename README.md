# Астрон · Design System

Стартовый фронтенд-проект для проектирования системы управления фитнес-залом. React, TypeScript, Vite и Lucide. Бэкенда нет: все данные находятся в памяти React и восстанавливаются при обновлении страницы.

## Запуск

Требуются Node.js 22.12+ и pnpm (версия указана в `package.json`).

```sh
pnpm install
pnpm dev
```

Локальный адрес: http://127.0.0.1:5173

```sh
pnpm typecheck  # Проверка TypeScript
pnpm build      # Готовое приложение в dist/
pnpm preview    # Просмотр собранного приложения
```

## Что уже есть

- **Ресепшен администратора**: клуб и рабочее место в шапке, быстрый ввод карты с открытием карточки клиента, журнал недавних посетителей, фильтры и восемь быстрых переходов справа, включая CRM. На телефоне журнал превращается в карточки, а переходы открываются отдельной кнопкой. CRM пока открывает экран-заготовку.
- **Клиенты**: поиск, фильтры статуса и абонемента, сортировка по имени, карточка клиента, добавление через форму.
- **Карточка клиента**: отдельная страница с основными сведениями, лицевым счётом, действиями и десятью вкладками. Абонементы фильтруются по состоянию, посещения связаны с журналом ресепшена. Финансовые операции и редактирование пока открывают заготовки сценариев.
- **Дизайн-система**: категории «Основы», «Логотипы», «Кнопки и поля», «Готовые блоки». Цвета с копированием HEX, примеры шрифтов, отступы, скругления, кнопки, формы, статусы, аватары и составные элементы.
- **Десктоп / Телефон**: переключатель в верхней панели. Телефон отображается в рамке 390 × 844. В узком окне приложение адаптируется автоматически.
- **Состояния**: с данными, пусто, загрузка, ошибка. Это управляемый предпросмотр: загрузка намеренно не заканчивается сама. На странице дизайн-системы состояния отключены.
- **Сброс**: кнопка со стрелкой в верхней панели возвращает исходные демоданные. В узком окне она находится в меню состояний.
- **Роли**: администратор, тренер, директор клуба, директор сети и маркетолог. В панели прототипа можно выбрать роль и увидеть соответствующую главную. На телефоне выбор роли находится под верхней панелью.

Выбранный экран, устройство, состояние и роль записываются в URL; ссылку можно открыть напрямую:

```text
/#/overview?device=desktop&state=default
/#/members?device=mobile&state=empty
/#/design-system?device=desktop&state=default
/#/overview?device=mobile&state=default&role=trainer
/#/overview?device=desktop&state=default&role=network-director
/#/client-profile?device=desktop&state=default&role=administrator&clientId=1001
```

Дата в макете зафиксирована на 1 ноября 2026 года. Показатели и посещения — вымышленные примеры, не аналитика списка клиентов. Мобильные и десктопные экраны используют одни компоненты и одни данные. Добавленные клиенты сохраняются при переключениях до перезагрузки страницы.

## Структура

```text
src/
  App.tsx                  # Оболочка, навигация, роли, рабочая зона и диалоги
  types.ts                 # Общие типы
  components/ui.tsx        # Переиспользуемые компоненты
  components/ClubLogo.tsx  # Общий логотип с заменой отсутствующего файла
  components/LogoGuidelines.tsx # Примеры и правила размещения логотипов
  components/AdminHeader.tsx # Рабочее место, карта и действия в шапке
  components/AdminQuickLinks.tsx # Общая панель быстрых переходов
  data/mock.ts             # Демо-клиенты, занятия, график и список экранов
  data/admin.ts            # Рабочие места, карты и журнал посещений
  data/clientProfile.ts    # Вкладки и вымышленные данные карточки клиента
  data/roles.ts            # Роли, пользователи, сеть, клубы и примеры главных
  data/branding.ts         # Название клуба и файлы логотипов
  data/profileBookings.ts  # Демо-предзапись в служебной карточке клиента
  pages/
    AdminOverview.tsx      # Главная администратора: журнал и быстрые переходы
    AdminSection.tsx       # Экраны-заготовки следующих разделов
    ClientProfile.tsx      # Полная карточка клиента и история
    Overview.tsx           # Ранний пример дашборда (не используется в навигации)
    RoleOverview.tsx       # Главные сотрудников и личный кабинет клиента
    Members.tsx            # Клиенты
    DesignSystem.tsx       # Каталог компонентов
  styles/
    tokens.css             # Цвета, шрифты, отступы, скругления
    app.css                # Компоненты и адаптация через container queries
    roles.css              # Переключатель ролей и примеры главных
    admin.css              # Рабочая шапка, журнал и адаптация ресепшена
    client-profile.css     # Карточка клиента и мобильные абонементы
    branding.css           # Логотипы и оформление стайлгайда
    design-system.css      # Единые отступы, скругления и выравнивание стайлгайда
    disclosures.css        # Внутренние отступы стрелок и выпадающих списков
```

## Как дорабатывать

1. Для изменения общей визуальной системы начните с `src/styles/tokens.css`.
2. Общие элементы добавляйте в `src/components/` и показывайте их в каталоге `DesignSystem.tsx`.
3. Новые экраны создавайте в `src/pages/`, добавляйте тип `Page`, запись в `pages` и пункт `navigation` в `App.tsx`.
4. Примерные данные меняйте в `src/data/mock.ts`. Для новых сценариев расширяйте тип `Scenario`, список `scenarios` и `StateContent`.

Внешние шрифты, API, база данных и аккаунты для работы прототипа не требуются.

Платные библиотеки в проекте запрещены. Перед добавлением зависимости проверяется возможность бесплатного коммерческого использования конкретного пакета и нужных функций. Текущие библиотеки приложения — React и React DOM (MIT), иконки Lucide (ISC); интерфейс использует собственные компоненты. Инструменты разработки также имеют бесплатные лицензии: Vite, плагин React, Prettier и типы React — MIT, TypeScript — Apache-2.0.

## Логотип клуба

В примерах используется «Астрон». По просьбе пользователя основной SVG — `public/brand/astron-black.svg`, чёрный на светлом фоне. Предоставленный белый оригинал `public/brand/astron-white.svg` сохранён и используется для примеров контрастности в стайлгайде. Настройки находятся в `src/data/branding.ts`. Для другого клуба достаточно добавить его настройки и связать их с клубом в `src/data/roles.ts`. Общий компонент сохраняет пропорции и показывает название, если файла нет. Правила для разработчиков: `docs/design/club-branding.md`; наглядные примеры доступны в категории «Логотипы» дизайн-системы.

## Палитра

Основной акцент — тёплый бордовый `#8A332C`, фон — кремовый нейтральный, вторичный текст — серо-зелёный `#606A5C`, выбор — светлый оттенок винного. Все основные цвета заданы в `src/styles/tokens.css`; страница дизайн-системы читает их из CSS и показывает актуальные HEX и контраст. Статусы имеют отдельные цвета и подписи, поля и фокус клавиатуры выделены контрастными границами. Правила, сочетания и результаты проверки находятся в `docs/design/color-palette.md`.

## Данные ролей

В `src/data/roles.ts` находятся `roles`, `demoUsers`, `demoNetworks`, `demoClubs` и `roleHomes`. У каждого демопользователя есть роль, сеть и список клубов. Все демо-клубы находятся в Йошкар-Оле.

Администратор видит ресепшен и журнал посетителей. Тренер — свои занятия; директор клуба — показатели филиала; директор сети — сводку трёх клубов; маркетолог — кампании. Каталог дизайн-системы доступен для просмотра в каждой роли как часть песочницы.

## Источник главной администратора

Старая система https://system.astron.club/ изучена только в режиме чтения. Правила работы сохранены в `AGENTS.md`, наблюдения — в `docs/references/astron-admin-home.md`. Быстрый ввод карты открывает профиль клиента; посещение создаётся только отдельным действием в прототипе. Для примера введите `100001` (карта Анны Смирновой). Фильтры, выбор ресепшена и новые посещения работают с данными в памяти. Неизученные разделы открывают явно обозначенные экраны следующего этапа.

Флаги `canViewMembers` и `canAddMembers` управляют примерами навигации и действий в интерфейсе; это моделирование ролей на фронтенде, а не серверная авторизация.

## Карточка клиента

Наблюдения по предоставленной пользователем странице сохранены в `docs/references/astron-client-profile.md`. Реальные фото, контакты и финансовые данные в проект не переносились. Введите демокарту `100001`: откроется страница Анны Смирновой. Сам ввод карты не создаёт посещение; для этого предусмотрены отдельная кнопка и подтверждение. При отмене регистрации карточка остаётся открытой. «Назад» возвращает к журналу или списку, из которого открыли клиента.

Вкладки: абонементы, инфо, посещения, финансы, комментарии, действия, предзапись, отзывы, звонки, переписка. Неизученные сценарии показаны как заготовки или пустые состояния. Телефон изначально замаскирован, раскрытие показывает только вымышленный контакт. Посещения используют память приложения; пример предзаписи хранится в `src/data/profileBookings.ts`. Для новых клиентов не создаются вымышленные прошлые покупки, баланс и демографические сведения.

## GitHub Pages

Проект подготовлен для статического хостинга в корне сайта или в подпапке репозитория: пути к файлам относительные, навигация использует hash-маршруты. Workflow `.github/workflows/pages.yml` устанавливает зависимости по lockfile, собирает `dist/` и публикует его через GitHub Pages. Для публикации в настройках репозитория Pages нужно выбрать источник GitHub Actions.
