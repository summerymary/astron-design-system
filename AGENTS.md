# Источник редизайна и ограничения

## Старая система — строго только просмотр

Источник: https://system.astron.club/.

По прямому требованию пользователя в старой системе разрешено **только читать и смотреть**. Нельзя менять, добавлять или удалять данные, регистрировать посещения, вводить номера карт для проверки/прохода, выполнять оплаты, изменять настройки и запускать команды. Можно изучать видимую страницу и открывать безопасные меню без выполнения действий.

Пользователь входит самостоятельно в браузере в реальном времени. Не запрашивать и не сохранять учётные данные, коды, cookies или токены. В заметках фиксировать структуру, названия полей и бизнес-смысл, без реальных данных клиентов, карт и финансовых записей.

## Новый прототип

Изменять новый React-прототип пользователь разрешил отдельно. Старую систему не подключать к прототипу; не использовать её API. Все демонстрационные действия выполняются на вымышленных данных в памяти React.

Сохранять переключатели ролей, десктопа/телефона и состояний. Источник ролей и демопользователей — `src/data/roles.ts`.

По последней просьбе пользователя оставить пять ролей: администратор, тренер, директор клуба, директор сети и маркетолог. Роли уборщика и клиента клуба удалены. Клиентская база и служебная карточка клиента сохраняются. Демонстрационные записи для вкладки «Предзапись» вынесены в `src/data/profileBookings.ts`. Город всех клубов — Йошкар-Ола. Под заголовком страницы «Клиенты» нет слогана.

Отступ стрелок раскрытия справа — 12 px, резерв текста внутри select — 36 px. Общие правила: `src/styles/disclosures.css`. Проверять отступы в рабочей зоне, переключателях ролей/состояний, фильтрах и мобильных быстрых переходах.

## Бесплатные библиотеки

Пользователь запретил платные библиотеки. Использовать только зависимости, которые позволяют коммерческое применение без оплаты лицензии. Перед добавлением проверять лицензию конкретного пакета и нужной функции, включая связанные зависимости. Не использовать платные Pro/Premium-модули, пробные лицензии или пакеты, бесплатные только для некоммерческих проектов. Обязательные уведомления лицензий сохранять. Текущее приложение использует React, React DOM и Lucide; компоненты интерфейса написаны в проекте без платного UI-набора.

## Название, логотип и язык стайлгайда

В примерах использовать клуб «Астрон». По прямой просьбе пользователя основной логотип — чёрная версия `public/brand/astron-black.svg` на светлом фоне. Она создана из предоставленного белого SVG изменением только заливок. Белый оригинал `public/brand/astron-white.svg` сохранять без изменений; использовать его в примерах контрастности на тёмных подложках. Общие правила контрастности логотипов в стайлгайде сохранены. Не обрезать и не растягивать рисунок. Настройки бренда — `src/data/branding.ts`; показывать логотип через общий `ClubLogo`. Для другого клуба задавать собственные название, файлы и подходящую подложку. Отдельный компактный знак «Астрона» не предоставлен: использовать букву «А», включая фавиконку. Правила и размеры: `docs/design/club-branding.md`.

Категория «Логотипы» должна сохранять правила для других клубов. Описания дизайн-системы писать простыми словами, образцы шрифтов — русским текстом-рыбой. Декоративный `ds-hero` удалён по просьбе пользователя. На неготовых экранах использовать безличные формулировки «будут разработаны», без «разработаем» и обещаний от лица команды.

## Цветовая система

По просьбе пользователя 6 ноября 2026 года добавлен генератор `src/lib/theme.ts` и выбор основного цвета в «Дизайн-система → Основы». Активные токены применяются через `ThemeProvider` ко всем экранам и остаются в памяти до перезагрузки. `tokens.css` и `ASTRON_TOKENS` сохраняют точную исходную палитру «Астрона». Каталог читает текущие значения из контекста. Статусы и файлы логотипов не перекрашивать. Светлый акцент корректируется по контрасту; сохранять исходный HEX отдельно от рабочего. Перед публикацией запускать `pnpm test:theme`. Подробности: `docs/design/adaptive-palette.md`.

По выбору пользователя основной акцент — бордовый (`--color-accent: #8A332C`). Значения палитры хранить в `src/styles/tokens.css`; каталог дизайн-системы читает цвета из этих токенов. Использовать белый текст на основном акценте, кремовый оттенок акцента для выбора и тёплые нейтральные оттенки для данных и поверхностей. Статусы успеха, внимания и ошибки сохраняют отдельные семантические цвета и текстовые подписи. При изменениях проверять контраст и видимость фокуса. Правила и проверенные сочетания: `docs/design/color-palette.md`.

Вторичный текст по выбору пользователя — `--color-muted: #606A5C`; `--color-subtle` ссылается на тот же цвет. Основной текст и смысловые статусы сохраняют отдельные цвета. Полный логотип «Астрона» размещается без видимой рамки и подложки (`logoFrameless: true`) на светлой поверхности; белые примеры в стайлгайде сохраняют контрастные подложки. Общая геометрия стайлгайда — `src/styles/design-system.css`: скругления карточек 16 px, внутренние отступы 24 px на десктопе и 16 px на телефоне, выравнивание парных блоков.

По просьбе пользователя в быстрых переходах администратора восемь пунктов, включая CRM. Он открывает отдельный экран-заготовку `section=crm`; бизнес-логика CRM ещё не разработана. Счётчик мобильных переходов формируется из списка, без жёстко заданной семёрки. Для бара используется `CupSoda` из бесплатной Lucide.

## Главная администратора: подтверждённые требования пользователя

1. Шапка с контекстом рабочей зоны.
2. Быстрый ввод карты клиента для регистрации посещения, в прототипе только с демоданными.
3. Таблица недавних посетителей как основной рабочий блок.
4. Быстрые переходы на другие страницы справа.

Не выдавать предположения о старой бизнес-логике за подтверждённые наблюдения.

## Подтверждённые наблюдения от 1 ноября 2026 года

Главная изучена после самостоятельного входа пользователя. В шапке: сотрудник, карта, клуб и ресепшен, «+ Посещение», «Бар», уведомления о звонках, состояние системы, онлайн-заявки, сообщения и отзывы. Рабочее место выбирается отдельным диалогом; в старой системе его открыли для просмотра и закрыли без сохранения.

Таблица «Недавние посетители»: №, время входа, карта, клиент, посещение, абонемент, клуб. Фильтры: период с датой и временем, пол, возраст, клуб, тип посещения, сортировка, уникальные клиенты. Карта ведёт к регистрации, имя — к информации о клиенте; переходы не запускались.

Правая панель: расписание, регистрация посещения, продажа услуг, клиенты, продажа товаров, коллагенарий, касса.

**Уточнение пользователя:** ввод карты открывает карточку клиента для просмотра данных и выбора дальнейшего действия (посещение, продажа и т. д.). Сам ввод не должен регистрировать посещение.

Подробные наблюдения, решения первого макета и открытые вопросы: `docs/references/astron-admin-home.md`. Использовать этот документ при дальнейшей работе над главной администратора. Не проверять поведение на реальных картах.

## Карточка клиента

По прямой ссылке пользователя 1 ноября 2026 года изучена полноценная страница `index.php?do=clientinfo&id=<client_id>`. Подтверждены фото и сведения клиента, баланс, кнопки действий и десять вкладок: абонементы (по умолчанию), инфо, посещения, финансы, комментарии, действия, предзапись, отзывы, звонки, переписка.

Новый прототип должен открывать страницу клиента вместо короткого модального окна. Данные и фото реального клиента не переносить. Не запускать операции и не раскрывать контакты в старой системе. Детали и ограничения: `docs/references/astron-client-profile.md`.

## Плотность списков

Пользователь просит показывать больше клиентов в рабочей области. В списке клиентов и журнале недавних посетителей использовать строки высотой 40 px с прежними размерами текста (уплотнение с 48 px по дополнительной просьбе). Общие параметры вынесены в токены `--table-record-*`. Не увеличивать вертикальные отступы обратно без явной причины. На телефоне сохранять удобные области нажатия.

Фавиконка `public/favicon.svg`, её версия в `index.html` и метатег `theme-color` должны совпадать с основным акцентом. При обновлении фавиконки менять версию URL, чтобы браузер загрузил новый цвет.
