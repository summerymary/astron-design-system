# Астрон — передача интерфейса разработчику

Актуальная спецификация оформления прототипа на 12 ноября 2026 года. Цель — перенести интерфейс в рабочую систему my-dev.astron.imbateam.tech, сохранив её серверную логику. Это интерфейс управления клубом, а не маркетинговый лендинг. Сам рабочий сайт этим набором не изменяется.

## Быстрый старт

- [Прототип](https://summerymary.github.io/astron-design-system/) — поведение, роли и страницы.
- [Живой стайлгайд](https://summerymary.github.io/astron-design-system/design-system.html) — настоящие компоненты с переключением тем.
- [Документ в браузере](https://summerymary.github.io/astron-design-system/developer/) — эта спецификация, полный справочник токенов и правил, печать в PDF через браузер.
- [Токены JSON](https://summerymary.github.io/astron-design-system/developer/design-tokens.json) — все базовые переменные, три готовые темы, смысловые цвета и контекстные CSS-переменные с источниками.
- [Токены CSS](https://summerymary.github.io/astron-design-system/developer/design-tokens.css) — готовые значения для подключения в другом приложении. Это токены, не самостоятельная библиотека компонентов.

Установка: Node.js 24, менеджер пакетов из packageManager в package.json. `pnpm install --frozen-lockfile`, затем `pnpm dev`; production — `pnpm build`. Платных библиотек нет: React, React DOM, Lucide, собственные компоненты. Лицензии — THIRD_PARTY_NOTICES.md.

## Цвет и тема

Астрон: акцент #8A332C, hover #722820, pressed #5B1F19, мягкий акцент #F6EBE6. Основные данные #181C24, обычный текст #3D4652, подписи #606A5C. Фон приложения #FDFDFC, поверхность #FFFFFF. Обычная граница #DCE1E7, граница поля #7C8794. Логотип #B32D3D — отдельный брендовый ресурс, не цвет всех действий.

Графит использует generatePalette('#111111'). Контраст сохраняет палитру Астрона и усиливает контуры: #B8AEA6 у панелей, #746C63 у полей. Вторая внутренняя линия 1 px вместе с внешней границей 1 px даёт визуальные 2 px, не меняя размеры. Фокус — самостоятельный внешний контур. Нет другого дизайна, тёмного бокового меню или другой сетки.

В прототипе используются `?theme=111111` и `?style=vivid`. В автономном CSS-экспорте тема выбирается атрибутом `data-astron-theme="astron|graphite|contrast"` на html. При React-переносе предпочтителен исходный ThemeProvider: он применяет токены, адрес, favicon и цвет браузерной панели. Не смешивать оба механизма одновременно.

Новый фирменный цвет проходит normalizeHex → generatePalette → visualStyleTokens. Генератор использует OKLCH/sRGB, ограничивает насыщенность до цветового охвата и проверяет контраст текста. Тёмный текст на ярком действии определяется отдельным --color-on-action. Статусы и виды услуг не перекрашиваются под бренд. Для обычного текста проверять контраст минимум 4.5:1; для управляющих границ и фокуса — 3:1. Реальные значения и проверки — test:theme.

## Состояния и общие компоненты

Кнопки: primary — следующий шаг/сохранение; secondary — нейтральная с рамкой; ghost — спокойное действие; accent — важное дополнительное действие с бордовой рамкой; danger/danger-ghost — удаление/опасное действие. «Отмена», закрывающая окно, нейтральная. Hover/pressed не сдвигают геометрию. Disabled не выполняет действие и не получает hover. Есть отдельный :focus-visible.

Поля: label сверху, помощь/ошибка снизу, обязательность обозначена текстом/звёздочкой. aria-invalid и aria-describedby связывают ошибку с полем. Ошибка красная, readonly отличается от disabled. Многострочный ввод выше однострочного. Чекбокс, radio, цветовая палитра, поле даты и сообщение — зарегистрированные специальные паттерны, их нельзя делать похожими на обычную кнопку.

Поиск: общий вид у SearchBox, ClientSearch, поиска каталога продажи и поиска внутри Select. Фильтр списка обновляет данные без отправки; ClientSearch принимает карту/ФИО/телефон и открывает клиента при выборе или Enter. Отдельной кнопки ↵ нет. Arrow Up/Down выбирают подсказку; Escape закрывает; X очищает. Поиск и выбор не списывают посещение и не выполняют оплату.

Select: один общий компонент с галочкой, поиском при числе вариантов больше семи, клавиатурой, закрытием снаружи/Escape и размещением панели по свободному месту. Меню «…» — DisclosureMenu; закрывается снаружи, при уходе фокуса и Escape, не поглощает нажатие внешнего действия. Пункты не дублируют соседние кнопки.

Статусы: успех/действует — зелёный; ожидание — янтарный; ошибка/отмена — красный; работа/доставка — синий; заморозка — фиолетовый; завершённый/неизвестный — нейтральный. Цвет всегда дополнен текстом. Использовать statusTone/feedbackTone, а не поиск частей слова.

Окна: заголовок и подписанное закрытие, удержание фокуса, возврат фокуса, Escape, общий ряд действий. Удаление и отмена записи — через ConfirmDialog с объектом и последствиями. Вложенное окно сохраняет блокировку прокрутки. ScreenLock снимается отдельным действием.

## Оболочка и адаптация

Компьютер от 1000 × 650: высота оболочки равна окну, шапка и навигация доступны, длинное содержимое прокручивается в workspace-page-body либо собственном списке. Цепочка flex/grid использует min-height:0 и min-width:0; несжимаемые панели не обрезают последний элемент. У таблиц допускается собственная горизонтальная прокрутка, но не у всей страницы.

На телефоне и маленьком окне обычная прокрутка страницы. Макет зависит от контейнера workspace, а не только viewport: это нужно и для демонстрационного режима «Телефон» на большом экране. Текущий нижний пункт выделен цветом, весом и иконкой без подложки. Длинные названия не перекрывают соседей.

Боковое меню 240 / 80 px, иконки и кнопка сворачивания не меняют координату. Сворачивание — строка 44 px без заливки, с однострочной подписью; в узком меню только иконка. У администратора меню по умолчанию открыто. Правой панели быстрых действий нет. Шапка: контекст клуба/ресепшена без повторного лого и звонков, поиск, «Новый клиент», «Расписание», «Товары» одинаковой высоты 44 px.

## Мобильное расписание

Узкий режим определяется контейнером календаря, включая предпросмотр телефона на широком мониторе. Дата занимает отдельную строку без переполнения; режим и разворачивание находятся рядом. Календарь имеет минимум 420 px высоты временной сетки; в «Весь день» доступен весь диапазон, названия не уменьшаются ради вмещения. На телефоне колонки залов от 240 px с внутренней горизонтальной прокруткой. Легенда интенсивности — компактный ряд «Низкая / Средняя / Высокая», длинная декоративная подсказка снизу скрыта.

## Прикладные паттерны, которые важно сохранить

- Карточка клиента: фото слева, справа ФИО с отчеством, данные, компактный счёт, посещение/продажа; редактирование и «…» у имени. Закреплённый комментарий заметен; все комментарии в общей истории. Наличие кабинета/приложения — в «Информации». Вкладки начинаются с абонементов, посещений и финансов.
- У администратора телефон скрыт, но редактируется в форме и доступен звонок; управляющим номер открыт. Маскирование в браузере не заменяет защиту и разграничение API.
- Абонементы клиента — компактный одинаковый список; при выборе покупки/посещения — цветные карты; в журнале — цвет текста. Цвет обозначает услугу, а не статус. Каталог: абонементы, персональные, корпоративные, исключения (оранжевые), товары/услуги ресепшена. Товары бара доступны только в баре.
- Регистрация из карточки сразу ведёт к выбору подходящего абонемента без повторного шага «Отметить». Проверять срок, остаток, время/день, возраст. Лайт: будни 06:30–16:00 и 20:00–23:10, выходные 07:00–22:10. Ланч: будни 12:00–15:00, выходные 17:00–22:10. Молодёжный: 14–23 года. Точные граничные проверки — lib/registration.ts и test:registration.
- Подсветка тарифа по предзаписи: от 60 минут до начала и до 30 минут после начала. Если вариантов несколько — явный выбор. До 14 лет требуется запись к тренеру из базы либо заметное предупреждение/подтверждение сопровождения по действующим правилам прототипа.
- Расписание: интенсивность зелёная/жёлтая/красная; названия приоритетнее метаданных. Недельная тепловая карта заполняемости у директоров — отдельный режим со своей легендой. Администратор записывает/снимает/отмечает присутствие и отменяет занятие, но не создаёт и не переносит тренировку. Полное занятие имеет резерв; освобождение места при резерве создаёт уведомление.
- Сообщения: время, отправлено/доставлено/прочитано, меню сообщений клуба, изменение/удаление с подтверждением, связь с клиентом. Не выдавать демостатус за реальную доставку.

## Как перенести в рабочее приложение

1. Сопоставить существующие экраны и данные с картой docs/references, не заменяя серверные операции демофункциями. Все реальные операции сохраняются на действующем backend.
2. Подключить токены и базовую типографику. Сделать общие компоненты в целевом проекте с теми же вариантами, состояниями и клавиатурой. Если стек позволяет, перенести исходные React-компоненты вместе с их зависимыми стилями.
3. Сначала перенести оболочку, шапку и навигацию, затем формы/поиск/Select/таблицы. Проверить три темы и размеры перед переносом прикладных страниц.
4. Заменить WorkspaceProvider и demo data адаптерами реального API. Сервер проверяет права роли, финансовые операции, ограничения тарифов, конфликт записей и резерв. Фронтенд только отображает состояния и помогает вводу.
5. Для каждого экрана проверить default/loading/empty/error, длинные имена, много записей, последнюю строку, увеличение текста, клавиатуру и телефон. Реальные данные не включать в этот публичный репозиторий.

Пример использования имеющихся компонентов:

```tsx
import { Button } from './components/ui';
import { SearchBox, Tabs } from './components/WorkspaceUI';
import { Select } from './components/Select';

<Button variant="accent" onClick={openSale}>Продать</Button>
<SearchBox value={query} onChange={setQuery} label="Поиск клиента" />
<Select aria-label="Клуб" value={club} onChange={(event) => setClub(event.target.value)}>
  <option value="central">Центральный</option>
</Select>
```

## Правило развития и проверка

Перед новым элементом найти существующий компонент. Новый вариант добавляется туда же. Новый тип зарегистрировать в registry.ts: назначение, метрики/токены, default/hover/pressed/focus/disabled/error/loading, клавиатура, телефон, темы; одновременно добавить рабочий пример в DesignRules/стайлгайд. Внешний вид — только в components.css, расположение — в CSS страницы нижнего слоя.

Запуск: `pnpm test:ui`, все профильные `test:*`, `pnpm build`. `pnpm docs:export` обновляет документ HTML и токены; `pnpm test:handoff` проверяет, что экспорт соответствует исходникам. Не редактировать сгенерированные файлы вручную. После изменения токенов/реестра/этого документа повторить экспорт.

Прототип хранит данные только в памяти вкладки. Платежи, оборудование, телефония, доставка сообщений, блокировка и фронтенд-роли — демонстрационные. Нельзя копировать их как готовую реализацию безопасности или финансов. Источники клуба использовались только для чтения; этот перенос не требует и не выполняет изменения в исходных системах.
