# Проверка прототипа — 8 ноября 2026

Проверен локальный production-прототип, без действий в исходных системах. Это экспертная проверка и контрольные сценарии, а не исследование с сотрудниками клуба.

## Охват

- 44 рабочих раздела, девять главных по ролям, клиентская база и карточка клиента: 55 маршрутов на 1280×720 и 390×844, всего 110 представлений. Проверялись содержимое, подписи элементов управления, размеры текста и переполнение документа. Внутренняя прокрутка широких таблиц и календаря учитывалась отдельно.
- Десять вкладок клиента, четыре состояния экрана, выбор фильтра тренера, поиск роли в длинном списке, создание вымышленного клиента с выбранным абонементом, сброс фильтров, открытие списка в модальном окне и Escape без закрытия формы.
- После изменений мобильных действий повторно проверены касса, продажа, нижняя навигация, закрытие панели, переход к полному каталогу, обычный телефон и режим телефона в десктопном предпросмотре. Меню выбора проверено также внутри полноэкранного расписания: Escape закрывает список, сохраняя полный экран.
- Автоматические проверки палитры, поиска, общих правил, расписания, сотрудников, сообщений, каталога, регистрации, оплаты; TypeScript и production build.

## Исправлено

| Проблема | Изменение |
| --- | --- |
| Открытое системное меню выбивается из оформления и зависит от ОС | Общий компонент Select во всех 40 местах выбора в исходниках, включая общую форму справочников. Светлая панель, тёплый бордовый, выбранный пункт с галочкой, высота от 44 px. Без новых библиотек. |
| Длинные списки трудно просматривать | Поиск при количестве вариантов больше семи, ясное пустое состояние. Неактивные варианты не выбираются. |
| Список может обрезаться формой или выйти за край | Панель выводится отдельно от ограничивающих контейнеров; учитывает свободное место сверху/снизу и визуальную область телефона. |
| Клавиатура и формы могут сломаться после замены native select | Стрелки, Home/End, Page Up/Down, Enter, Escape и Tab; нативный элемент сохраняет данные формы и required-проверку. Фокус модального окна игнорирует скрытые элементы. |
| На телефоне поиск клиента и статус сжаты в одну строку | Поиск на всю ширину, фильтры и статус отдельной строкой. |
| Быстрые переходы закрывают кассу и нижние записи | Плавающая плашка удалена. Нижний пункт «Действия» открывает отдельное окно с шестью переходами и кнопкой «Все разделы». |
| На телефоне нет прямой продажи из шапки | Добавлена кнопка «Продать». Из карточки клиента продажа получает текущего клиента. Кнопки шапки от 44 px. |
| В production расписание возвращает крупный заголовок | Уточнён приоритет CSS: рабочая строка и название 20 px остаются компактными. |
| Лишние декоративные элементы | Убрана повторная стрелка выбора состояния и слоган формы клиента; полное рабочее место доступно в подсказке и доступном названии. |
| Некорректная подпись количества занятий | 1 занятие / 2 занятия / 18 занятий. |

Новый фон #FDFDFC включён в тот же набор. Границы карточек и вторичный текст сохраняют различимость; контраст #606A5C на фоне — 5,56:1.

## Что рекомендую следующим шагом

1. **Широкие таблицы на небольшом ноутбуке.** Переполнения всей страницы нет, но часть столбцов требует внутренней прокрутки. Полезен выбор видимых колонок с сохранением предпочтения сотрудника. Имя клиента и основное действие лучше всегда оставлять видимыми.
2. **Карточка клиента.** Имя, карта, статус, телефон, баланс и действия нужны сразу. Пол, организация и часть справочных сведений используются реже; их лучше объединить в раскрываемое «Подробнее», не теряя доступ к данным.
3. **Расписание в нескольких залах.** При большом количестве залов полезны нынешние фильтры, список и полный экран. Следует проверить на реальном рабочем мониторе, нужен ли постоянный обзор всех залов или чаще используется один зал. Уменьшать текст ради помещения 18 занятий не следует.
4. **Проверка с сотрудниками.** Дать администратору, тренеру и управляющему задания: найти клиента по телефону, зарегистрировать посещение по нужному абонементу, продать товар ресепшена, перенести занятие и найти персональную заметку. Поиск ошибок и число лишних шагов важнее субъективной оценки «красиво».

Рекомендации выше не выданы за реализованные функции. Новые серверные правила, реальные продажи, авторизация и данные источников не подключались.
