# Палитра из одного цвета

На отдельной странице `design-system.html`, в разделе «Основы», находится блок «Цвета вашего клуба». Можно выбрать цвет, ввести HEX из трёх или шести символов, попробовать готовый пример и вернуть исходную палитру «Астрона». Образцы меняются сразу. Рядом с HEX показана компактная палитра: главный и дополнительный цвета, подписи, фон и границы. Нажатие копирует код. Кнопка «Скопировать CSS» копирует весь набор переменных.

Дизайн-система и прототип — два отдельных HTML-документа с собственной шапкой и точкой входа. В стайлгайде нет рабочих панелей, ролей и ресепшена. Старые ссылки `#/design-system?...` перенаправляются на новую страницу. Ссылка «Открыть прототип» передаёт выбранный цвет в параметре `?theme=F0FC03`; ссылка на дизайн-систему находится в панели прототипа, за пределами навигации продукта. Переход открывается в отдельной вкладке.

Цвет сохраняется в URL, поэтому обновление страницы и передача ссылки сохраняют тему. Переключение роли, устройства, экрана и состояния тоже её сохраняет. Другие демоданные остаются только в памяти. Сохранения на сервере и привязки к конкретному клубу пока нет.

## Готовые темы

| Тема | Основной цвет | Сопутствующие оттенки |
| --- | --- | --- |
| Астрон | `#7A263A` | Графитовый текст, светло-серые поверхности и серо-зелёные подписи |
| Глубокий синий | `#173B70` | Холодные светлые фоны и сдержанные серые |
| Тёмный лес | `#164B3B` | Светлые нейтральные фоны с зелёным оттенком |
| Лайм | `#F0FC03` | Холодный графитовый `#243341`, подписи `#5F676E`, фон `#F5FAFE` |
| Графит | `#111111` | Нейтральные серые |

## Что меняется

- Основные кнопки, наведение, нажатие, фокус и активные разделы.
- Светлые выделения и фоны с небольшим оттенком выбранного цвета.
- Нейтральный текст, подписи, разделители и границы полей.
- Цвет вкладки браузера и фон демонстрационной фавиконки с буквой «А».

Успех, предупреждение, ошибка, информация и заморозка сохраняют отдельные цвета и текстовые подписи. Аватары сохраняют демонстрационные цвета. Файлы логотипов не перекрашиваются: для них действуют [правила логотипов](club-branding.md).

## Выбранный цвет и цвет кнопок

Выбранный фирменный цвет сохраняется как исходное значение. Обычно для интерфейса рассчитывается читаемый рабочий оттенок с белым текстом. Почти чёрный цвет немного осветляется, чтобы состояния наведения и нажатия различались. Для яркого светлого жёлтого/лайма предусмотрена пара: яркие главные кнопки с тёмным текстом и холодный графитовый для навигации, выделений и фокуса. Контрастная графитовая граница делает светлую кнопку различимой на фоне. Подписи и поверхности не становятся оливковыми. В предпросмотре показаны оба значения и объяснение.

Исходная палитра «Астрона» — специальный сохранённый набор: `#7A263A` с серо-зелёными подписями `#606A5C`. Возврат к ней восстанавливает прежние значения точно.

## Расчёт для разработчиков

Чистая функция `generatePalette(primaryHex)` в `src/lib/theme.ts` возвращает `{ primary, adjusted, appearance, tokens }`. `primary` — нормализованный исходный HEX, `adjusted` — отличается ли рабочий акцент, `appearance` — `standard` либо `citrus`, `tokens` — все цветовые CSS-переменные. `THEME_PRESETS` содержит готовые темы. Неподходящий ввод вызывает ошибку; форма показывает подсказку и оставляет последнюю рабочую палитру.

```ts
const palette = generatePalette('#F0FC03');
palette.primary; // исходный фирменный цвет
palette.tokens['--color-action']; // главная кнопка: #F0FC03
palette.tokens['--color-on-action']; // текст кнопки: #243341
palette.tokens['--color-accent']; // навигация и фокус: #243341
paletteToCss(palette); // готовый блок :root
```

Расчёт выполняется в [OKLCH / Oklab](https://www.w3.org/TR/css-color-4/#ok-lab). Обычно оттенок наследуется от исходного цвета; для ярких цитрусовых (L > 0,82, C > 0,1, H 90–125°) используется холодная графитовая семья для второстепенных элементов. Светлота подбирается по назначению, насыщенность нейтральных цветов ограничивается. Если оттенок выходит за sRGB, насыщенность уменьшается при сохранении светлоты и тона. Для серых цветов не добавляется случайный цветной оттенок. Итоговые значения — обычные HEX, дополнительные библиотеки не нужны.

Контраст проверяется по относительной яркости уже округлённых HEX. Для сгенерированного акцента, его состояний и вторичного текста используется запас до 4,7:1; для границ полей — 3,15:1. Это обеспечивает минимум 4,5:1 для обычного текста и 3:1 для значимых границ на используемых светлых поверхностях. См. [контраст текста WCAG](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) и [контраст элементов управления](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html). Декоративные разделители могут быть светлее и не должны заменять границы полей. Проверка палитры не заменяет аудит доступности новых компонентов.

`ThemeProvider` применяет переменные ко всему документу. Каталог дизайн-системы получает тот же набор из контекста: образцы, HEX и показатели контраста обновляются вместе с интерфейсом. `src/styles/tokens.css` остаётся стартовой палитрой до запуска React. При изменении исходной палитры необходимо синхронно менять `ASTRON_TOKENS` и CSS; тест проверяет совпадение.

## Проверка

`pnpm test:theme` проверяет исходную палитру, нормализацию ввода, детерминированность, неизменность статусов, экспорт CSS и контраст 1015 палитр, включая текст кнопок во всех состояниях и контур яркой кнопки. В набор входят белый, чёрный, серые, насыщенные RGB/CMY, готовые темы и 1000 воспроизводимых случайных цветов. Эта проверка запускается перед публикацией GitHub Pages.
