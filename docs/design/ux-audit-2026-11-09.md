Правила — `messenger.md` и `layout.md`.

В итоговой сборке проверены 65 целей при 1280×720, те же 65 при 1024×650 (с раскрытым меню администратора) и 65 на 390×844. На компьютере нет прокрутки всего окна, на телефоне — горизонтального переполнения. При проверке малого экрана устранено переполнение трёх таблиц из-за абсолютно размещённых подписей для программ чтения. Все записи доступны во внутренней прокрутке; ошибки консоли не обнаружены. Это проверка маршрутов/компоновки, а не перебор всех бизнес-комбинаций.

Отдельно проверены отправка текста с переносом, сохранение времени после редактирования, отметка «изменено», отмена и подтверждение удаления, отсутствие меню у входящих, возврат в тот же чат из карточки. На телефоне проверены меню исходящего сообщения, редактирование, контакт без карточки и контакт с карточкой. Галочки доставки/прочтения показаны на демонстрационных примерах; внешняя отправка и API не используются.

## Рекомендации

1. Для повседневной работы открывать «Заявки», а настройку сценариев использовать реже. Следующее действие и срок полезнее постоянно видимой схемы процесса.
2. Перед подключением реальных данных утвердить названия сценариев и статусов вместе с маркетологом; текущий процесс пробного занятия — демонстрационный пример.
3. Полный финансовый доступ бухгалтера оставлен по просьбе пользователя. В рабочем продукте понадобятся серверные права и журнал действий; переключатель роли прототипа их не заменяет.
4. Сложные отчёты, кассовое оборудование и расчёт зарплаты требуют отдельных бизнес-правил. Сейчас они не выполняют реальных операций.

Исходные сайты во время этой доработки не открывались. Данные и API исходных систем не использовались; платных и новых зависимостей нет.
