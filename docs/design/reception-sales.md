# Постоянные действия и продажи ресепшена

Для администратора быстрые переходы находятся в общей оболочке всех страниц, включая пустые состояния и ошибки. Справа одна закреплённая панель. При небольшой ширине остаются подписанные для скринридера иконки с подсказками, на телефоне — постоянная кнопка открытия над нижним меню. Из карточки клиента продажа сохраняет выбранного клиента. Полноэкранный режим календаря остаётся отдельным режимом просмотра.

Продажа товаров ресепшена использует отдельный каталог `retail-products`: носки, резинки для волос и тапочки. Его складские документы — `retail-inventory`. Товары бара хранятся отдельно в `products`, документы — `inventory`, и доступны только внутри раздела бара: заказ, каталог, продажи, категории, витрины и склад бара. В справочнике, продаже ресепшена, общем складе, кассе, отчётах, финансовых операциях клиента и детализации зарплаты барные позиции не показываются.

В продаже любого вида покупки клиент выбирается через общий поиск по карте, ФИО или телефону. Несколько совпадений требуют выбора; поиск не регистрирует посещение и не подтверждает оплату. Затем выбираются покупка и, для товаров, количество. Перед подтверждением видны клиент, карта, контакты, описание покупки, цена, скидка и итог.

Способы оплаты: наличные, безналичная оплата, подарочная карта, кредит и составная оплата. Сумма частей должна точно совпадать с итогом с точностью до копеек. Подарочная карта требует достаточного остатка. В долг записывается только неоплаченная часть. Склад уменьшается после успешной проверки оплаты; повторное подтверждение блокируется. Чек — только предварительный демопросмотр, без фискализации и печати.

Скидки 5/10/15%, два подарочных остатка и фиксация задолженности — предложения прототипа на вымышленных данных, а не подтверждённые правила реальной кассы. Всё сбрасывается вместе с демоданными. API исходных сайтов, реальные платежи, сообщения, кассы и принтеры не подключены.

Проверки: `pnpm test:checkout`, `test:search`, `test:workspace`, `test:staff`, `test:catalog`, `test:registration`, production build и проверка интерфейса на компьютере/телефоне. Изменения остаются локальными до прямой просьбы о commit/push.

## Разделы продажи и поиск — 8 ноября

В продаже сначала выбирается один из пяти разделов: «Абонементы», «Персональный тренинг», «Корпоративные абонементы», «Исключения», «Товары и услуги». Внутри — позиции и возврат ко всем разделам. Поиск по названию на первом уровне ищет по всему каталогу; внутри — только в выбранном разделе. Регистр букв, ё/е и порядок слов не мешают поиску. Черновики и архивные позиции не продаются; бар исключён из поиска.

Пользователь уточнил: «Исключения» — специальные тарифы, акции и социальные предложения. Добавлены два вымышленных примера и один корпоративный тариф. Цены, периоды акций, документы для льгот и допуск по организации требуют согласования перед настоящим внедрением.

В карточке клиента вместо пластиковых карт используется список со статусом, сроком и остатком. Пластиковые карты сохранены для выбора покупки и абонемента при регистрации. Поиск клиента при регистрации показывает такой же список совпадений, как в шапке, с ФИО, телефоном и картой; контейнер не должен обрезать подсказки. Выбор клиента не создаёт посещение.

Пользователь прямо запросил отправить весь накопленный набор в GitHub. Это разрешение относится к текущему обновлению, а не будущим коммитам и push.
